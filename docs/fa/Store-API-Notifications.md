# رابط Store API: اعلان‌ها

هر چیزی که فروشگاه خودش به کاربر خبر می‌دهد — پرداختی که تایید یا رد شد، سرویسی که به‌زودی تمام می‌شود، چند روز هدیه،
یک تمدید، پاسخ پشتیبانی به یک تیکت — ۱۸۰ روز برای وب‌سایت نگه داشته می‌شود، چه در تلگرام به او رسیده باشد، چه با ایمیل،
چه اصلا نرسیده باشد. اگر حساب تلگرام داشته باشد به چت تلگرامش می‌رود؛ کاربری که ندارد — یا ربات را بلاک کرده — اگر ایمیل
داشته باشد و ایمیل فروشگاه فرستاده شود، آن را **با ایمیل** و به نام فروشگاه می‌گیرد. تغییر روش‌های ورود به حساب به هر دو
می‌رود ([ورود تازه](Store-API-Account.md#ورود-تازه)). هر اعلان یک متن دارد: متن ربات خود فروشگاه، همان‌طور که ربات فرستاده
(یا می‌فرستاد). آنچه اعلان نیست در این فهرست نمی‌آید: ارسال همگانی به گروهی از کاربران، و پاسخ‌های گفتگویی که کاربر در
حال انجامش است — صفحه‌های ربات، یا تایید خود یک خرید یا تمدید با کیف پول (در وب‌سایت، خود پاسخ پرداخت آن را می‌گوید).
مسیرها زیر [آدرس پایه](Store-API.md#آدرس-پایه) هستند؛ همه با توکن Bearer کاربر.

## فهرست اعلان‌ها

پاسخ `200` به <code dir="ltr">GET /notifications?unread=&amp;page=</code>:
```json
{
  "notifications": [
    {
      "id": 306,
      "type": "ticket_answered",
      "text": "💬 پاسخ پشتیبانی به تیکت #12\n📌 قطعی اتصال\n\nمشکل سرور برطرف شد؛ لطفا یک بار اتصال را قطع و دوباره وصل کنید.",
      "html": "💬 <b>پاسخ پشتیبانی به تیکت #12</b><br>📌 قطعی اتصال<br><br>مشکل سرور برطرف شد؛ لطفا یک بار اتصال را قطع و دوباره وصل کنید.",
      "subject": { "type": "ticket", "id": 12 },
      "read": false,
      "created_at": "2026-10-08T10:40:00+00:00"
    },
    {
      "id": 305,
      "type": "payment_rejected",
      "text": "رسید پرداخت سفارش #52 تایید نشد.\nتوضیح پشتیبانی: مبلغ واریزی با مبلغ سفارش یکی نیست.",
      "html": "رسید پرداخت سفارش #52 تایید نشد.<br>توضیح پشتیبانی: مبلغ واریزی با مبلغ سفارش یکی نیست.",
      "subject": { "type": "order", "id": 52 },
      "read": true,
      "created_at": "2026-10-07T13:10:00+00:00"
    }
  ],
  "meta": { "page": 1, "per_page": 25, "total": 2, "last_page": 1, "unread": 1 }
}
```

(متن‌های بالا فقط نمونه‌اند: متن هر اعلان از متن‌های ربات خود فروشگاه است، همان‌طور که ربات فرستاده.)

- پارامتر `unread=true` فقط خوانده‌نشده‌ها را می‌آورد (`1`، `on` و `yes` هم همین معنی را دارند)؛ اگر نفرستید، همه را
  می‌آورد. `meta.unread` تعداد خوانده‌نشده‌هاست، هر صفحه‌ای که نشان داده شود.
- فیلد `text` — متن ساده: بدون قالب‌بندی، شکستگی خط‌ها به شکل <code dir="ltr">\n</code> (از `white-space: pre-line`
  استفاده کنید)، و ایموجی پرمیوم به شکل ایموجی ساده‌اش.
- فیلد `html` — HTML امن: فقط `b`/`strong`، `i`/`em`، `u`/`ins`، `s`/`strike`/`del`، `code`، `pre`، `blockquote`،
  <code dir="ltr">&lt;span class="tg-spoiler"&gt;</code>، `<a href>` به یک آدرس http(s) و `<br>`؛ همه متن‌ها escape
  شده‌اند. آن را همان‌طور که هست در صفحه بگذارید (`dangerouslySetInnerHTML`) و <code dir="ltr">.tg-spoiler</code> را به
  شکل اسپویلر نشان دهید (پنهان تا وقتی رویش بزنند).
- فیلد `subject` — اینکه اعلان درباره چیست، برای لینک دادن: یکی از سفارش‌هایش
  (<code dir="ltr">GET /orders/{id}</code> — اعلان یک پرداخت درباره سفارش آن است)، سرویس‌هایش
  (<code dir="ltr">GET /subscriptions/{id}</code>) یا تیکت‌هایش (<code dir="ltr">GET /tickets/{id}</code>)؛ و `null` اگر
  چیزی نباشد — حسابش، سرویسی که حذف شده، ردیف کس دیگری. فقط سرویس ممکن است از آن موقع از بین رفته باشد (`404`: پشتیبانی
  حذفش کرده)؛ سفارش می‌ماند — سفارشی که کسی پرداختش نکرده با وضعیت `cancelled` بسته می‌شود — و تیکت هم.

## انواع اعلان

| `type` | درباره | `subject` |
|---|---|---|
| `payment_settled` | پرداختی که تایید شد — رسید با تایید پشتیبانی، پرداخت آنلاین با تایید درگاهش: سرویس تحویل شد، کیف پول شارژ شد — یا سفارشی که تحویل نشد: تحویل ناموفقی که پشتیبانی آن را تمام می‌کند، یا سفارشی که هیچ‌وقت تحویل نمی‌شود (`failure` آن `first_purchase_used` یا `service_changed_hands`: [چرا سفارش ناموفق شد](Store-API-Buying.md#چرا-سفارش-ناموفق-شد)) و پشتیبانی پرداختش را با کاربر تسویه می‌کند | سفارش |
| `payment_credited` | پرداخت آنلاینی که بعد از بسته شدن سفارشش رسید (از راه دیگری پرداخت شده، لغو شده یا منقضی شده): پولش به کیف پول رفت | سفارش |
| `payment_rejected` | رسیدی که رد شد، با دلیلش | سفارش |
| `order_cancelled` | سفارشی که پشتیبانی لغوش کرد | سفارش |
| `payment_refunded` | پرداختی که به کیف پول برگشت | سفارش |
| `topup_refunded` | شارژ کیف پولی که برگردانده شد و مبلغش از کیف پول برداشته شد | سفارش |
| `wallet_sent`، `wallet_received` | پولی که از کیف پولش برای کاربر دیگری فرستاد، یا پولی که کاربر دیگری برایش فرستاد («انتقال موجودی»، [انتقال موجودی](Store-API-After-Buying.md#انتقال-موجودی-به-کاربر-دیگر)) | `null` |
| `payment_reminder` | یادآوری پرداخت کارتی که هیچ‌وقت تمام نشد | سفارش |
| `service_disabled`، `service_enabled` | سرویسی که پشتیبانی خاموشش کرد، یا دوباره روشنش کرد | سرویس |
| `service_deleted` | سرویس فعالی که پشتیبانی حذفش کرد | `null` |
| `service_moved` | سرویسی که به سرور دیگری منتقل شد — با لینک تازه‌اش | سرویس |
| `service_transferred` | سرویسی از او که پشتیبانی به کاربر دیگری داد ([انتقال سرویس](Store-API-After-Buying.md#انتقال-سرویس-به-کاربر-دیگر)) | `null` |
| `service_received` | سرویسی که به او داده شد، از طرف مالک قبلی‌اش یا پشتیبانی — مالک قبلی تا وقتی او لینک را عوض نکند هنوز لینک را دارد | سرویس |
| `service_granted` | روز یا حجمی که به یک سرویس اضافه شد | سرویس |
| `expiry_reminder`، `traffic_reminder` | سرویسی که به‌زودی تمام می‌شود، یا حجمش رو به پایان است | سرویس |
| `auto_renewed` | سرویسی که با کیف پول تمدید شد | سفارش (تمدید) |
| `auto_renew_short` | موجودی کیف پول برای تمدید خودکار کافی نیست | سرویس |
| `renewal_failed` | تمدید خودکاری که پرداخت شد ولی انجام نشد: تحویل ناموفقی که پشتیبانی آن را تمام می‌کند — یا، اگر سرویسش در این میان به کاربر دیگری داده شده (`service_changed_hands`)، هیچ‌وقت انجام نمی‌شود و پشتیبانی پرداخت را با کاربر تسویه می‌کند | سفارش |
| `referral_joined`، `referral_commission`، `referral_commission_back` | تازه‌واردی با کد دعوت او آمد؛ پورسانتی گرفت؛ پورسانتی از کیف پولش پس گرفته شد، چون شارژ کیف پولی که آن را آورده بود برگردانده شد | `null` |
| `referral_start_gift`، `referral_reward` | هدیه شروعی به کیف پولش آمد (هدیه معرف برای یک تازه‌وارد، یا هدیه خود تازه‌وارد)؛ سرویسی به خاطر دعوت‌هایش رایگان به او داده شد — خود سرویس با یک `payment_settled` می‌آید | `null` |
| `agency_approved`، `agency_rejected`، `agency_changed`، `agency_revoked` | نمایندگی یک نماینده: درخواستش تایید یا رد شد، شرایطش عوض شد، نمایندگی‌اش تمام شد | `null` |
| `agency_traffic_short` | سفارشی که ربات او نتوانست تحویل دهد: حجم نماینده برایش کافی نیست | `null` |
| `agency_expiring`، `agency_minimum_short`، `agency_suspended`، `agency_resumed` | پایان نمایندگی‌اش نزدیک است؛ ماه رو به پایان است و حجمی که خریده از کف خرید ماهانه‌اش کمتر است؛ فروش ربات او متوقف شد، یا دوباره باز شد ([شرایط فروش](Agency.md#شرایط-فروش-پایان-و-کف-خرید-ماهانه)) | `null` |
| `way_in_added`، `way_in_removed` | حساب تلگرام، حساب گوگل یا ایمیلی که به حسابش اضافه شد، یا از آن برداشته شد | `null` |
| `password_changed` | رمز عبورش گذاشته یا عوض شد (`PUT /me/password`)، بازنشانی شد، یا با یک ادغام گذاشته شد ([پیشنهاد ادغام](Store-API-Account.md#پیشنهاد-ادغام))؛ ایمیلی که همراه رمز عبورش اضافه شود با `way_in_added` خبر داده می‌شود | `null` |
| `two_factor_enabled`، `two_factor_disabled` | ورود دومرحله‌ای‌اش روشن یا خاموش شد — به دست خودش یا پشتیبانی | `null` |
| `account_merged` | حساب دیگری از او با این حساب یکی شد | `null` |
| `second_step_locked` | مرحله دوم ورودش آن‌قدر اشتباه زده شد که تا مدتی بسته است: کسی رمز عبورش را دارد | `null` |
| `email_codes_failed` | کدهایی که به ایمیلش فرستاده شد آن‌قدر اشتباه زده شد که تا مدتی کدی فرستاده نمی‌شود | `null` |
| `ticket_answered` | پشتیبانی به تیکتش پاسخ داد — متن تا اندازه‌ای که در یک پیام تلگرام جا می‌شود کوتاه شده؛ متن کامل در تیکت است | تیکت |
| `ticket_closed` | پشتیبانی تیکتش را بست | تیکت |
| `loyalty_tier_up` | سفارشی که تحویل شد او را به سطح وفاداری بالاتری برد، با مزایای آن ([سطوح وفاداری](Loyalty-Cashback-And-Draws.md#سطوح-وفاداری)) | `null` |
| `cashback_earned` | سفارشی که تحویل شد برایش کش‌بک به کیف پولش آورد ([کش‌بک](Loyalty-Cashback-And-Draws.md#کش‌بک)) | سفارش |
| `lottery_won` | در قرعه‌کشی شبانه فروشگاه میان خریداران برنده شد و جایزه‌اش را گرفت ([قرعه‌کشی شبانه](Loyalty-Cashback-And-Draws.md#قرعه‌کشی-شبانه)) | `null` |

اعلان‌های روش‌های ورود به حساب — `way_in_added`، `way_in_removed`، `password_changed`، `two_factor_enabled`،
`two_factor_disabled`، `account_merged`، `second_step_locked`، `email_codes_failed` — هم به چت تلگرامش می‌روند و هم به
ایمیلش.

اعلانی را که `subject` آن `null` است با نوعش لینک کنید: صفحه زیرمجموعه‌گیری، تنظیمات امنیتی، کیف پول. این فهرست با رشد
فروشگاه بلندتر می‌شود: اعلانی از نوع ناشناخته را با متنش نشان دهید، و فقط وقتی لینکش کنید که نوع `subject` آن را
می‌شناسید.

## خوانده‌شده کردن

پاسخ `POST /notifications/read` تعداد اعلان‌هایی است که خوانده‌نشده مانده‌اند:

درخواست `POST /notifications/read`:
```json
{ "ids": [306] }
```

پاسخ `200` به `POST /notifications/read`:
```json
{ "unread": 0 }
```

- بدنه <code dir="ltr">{ "ids": […] }</code> همان‌ها را خوانده‌شده می‌کند، حداکثر ۱۰۰ تا. شماره‌ای که مال او نیست چیزی را
  عوض نمی‌کند و خطا هم نیست.
- بدنه `{}` همه را خوانده‌شده می‌کند.
- لیست خالی چیزی را عوض نمی‌کند. هر چیزی جز لیستی از عددها، یا بیش از ۱۰۰ شماره، `422` روی `ids` می‌گیرد
  (`شناسه‌ها باید لیستی از حداکثر 100 شماره اعلان باشد.`).

اعلانی که پیش‌تر خوانده شده زمان خوانده شدنش را نگه می‌دارد. اعلان‌های یک تیکت با خود تیکت هم خوانده‌شده می‌شوند:
با `POST /tickets/{id}/read` ([گفتگو](Store-API-Support-Tickets.md#گفتگو)) — یا وقتی ربات آن تیکت را به کاربر نشان دهد.

## زنگوله اعلان‌ها

فیلد `unread_notifications` در `GET /me`، `meta.unread`، یا پاسخ `POST /notifications/read`. تا وقتی صفحه‌ای از داشبورد
باز است، `GET /me` را تقریبا هر دقیقه یک بار دوباره بخوانید، و هر بار که تب دوباره دیده می‌شود هم.
