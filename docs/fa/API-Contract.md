# قرارداد API

هر اندپوینتی که PHP پاسخ می‌دهد یک بار، با OpenAPI 3.0.3، توصیف شده است: `resources/api/openapi.yaml`. هر دو طرف به
آن پایبند نگه داشته می‌شوند — تست‌های PHP هر درخواستی را که می‌فرستند و هر پاسخی را که می‌گیرند با آن اعتبارسنجی
می‌کنند، نوع‌های TypeScript پنل‌ها از روی آن تولید می‌شوند، و تست‌های پنل‌ها هر درخواستی را که می‌فرستند با آن
می‌سنجند. هر ناهمخوانی میان سرور و یک کلاینت پیش از اینکه به یک فروشگاه برسد یک تست را شکست می‌دهد. مرجع‌های تولیدشده
(به انگلیسی: [پنل‌ها](../Panels-API-Reference.md)، [Store API](../Store-API-Reference.md)،
[API مدیران](../Store-Admin-API-Reference.md)، [اسکیماها](../API-Schemas.md)) از روی همین فایل نوشته می‌شوند.

## آنچه توصیف در بر دارد

- **هر عملیات** `routes/api.php`، همراه اسکیمای هر پاسخ موفق. خطاها یک شکل مشترک دارند، `ErrorResponse`
  (`{message, errors?, request_id}`)، زیر `default`.
- **شیءهای بسته** (`additionalProperties: false`): فیلدی که سرور می‌فرستد، یا درخواستی همراه دارد، و توصیف آن را ندارد
  یک خطاست، هرگز چیز اضافه‌ای که بی‌صدا بگذرد. شیءای بدون فیلد یا نگاشتی (map) است از آنچه `additionalProperties` آن می‌گوید، یا
  خالی است. در یک پاسخ هر فیلد `required` است، و هر جا ممکن است null باشد `nullable`.
- **بدنه هر درخواست.** هر POST، PUT یا PATCH یک اسکیمای `requestBody` با نام دارد (تا تولیدکننده یک نوع بسازد، مثلا
  `PlanRequest`) یا با `x-no-body: true` می‌گوید هیچ بدنه‌ای نمی‌گیرد. یک فیلد درخواست وقتی `required` است که سرور
  درخواست را بدون آن رد کند؛ عددها می‌توانند به‌صورت عدد JSON یا متن بیایند (`WholeNumberInput`، `AmountInput`)، و
  سوییچ‌ها به‌صورت boolean. یک خانواده از درایورها با یک `oneOf` ذخیره می‌شود که برای هر درایور یک شکل بسته دارد
  ([درایورها](Drivers.md))، تا درخواست دقیقا با فیلدهای درایور خودش سنجیده شود؛ آنچه فرم یک درایور نگه می‌دارد
  به‌صورت `DriverValues` پاسخ داده می‌شود.
- **مسیرهای مشترک هر دو پنل** یک بار توصیف می‌شوند، زیر <code dir="ltr">/api/{panel}/…</code> با پارامتر مسیر `Panel`
  (admin، agent)؛ آنچه فقط یک پنل دارد زیر <code dir="ltr">/api/admin/…</code> یا <code dir="ltr">/api/agent/…</code>
  است. هر عملیات پنل مدیریت هدر `X-Shop` را می‌گیرد (فروشگاهی که تب آن نشان می‌دهد)، و خواندن یک فایل به‌جای آن
  پارامتر query `shop` را می‌گیرد — یک `<img>` هیچ هدری نمی‌فرستد.
- **هدر `Idempotency-Key`** در نوشتنی که ممکن است دوباره فرستاده شود، برای هر نوع نوشتن پارامتر جداگانه خودش است
  (`IdempotencyKey` برای پرداخت سفارش، `TransferKey`، `ManualOrderKey`، `WalletAdjustmentKey`، `TrafficAdjustmentKey`،
  `TicketAnswerKey`): جایی که سرور درخواست بدون آن را رد می‌کند اجباری است، و توضیح آن می‌گوید درخواست تکراری چه پاسخی
  می‌گیرد و کدام تغییر درخواست رد می‌شود.
- **نشانگرهای extension**:
  - نشانگر `x-staff` روی عملیاتی از کار روزانه فروشگاه که مدیران سایت هم آن را دارند — `true`، یا `StaffGrant`ی که
    فروشگاه برای آن باید بدهد — و `x-staff-recent: true` جایی که بدون مجوز یک ورود تازه می‌خواهد (تایید یک پرداخت).
    این مسیرها هرگز جداگانه نوشته نمی‌شوند: `tests/Support/ApiDescription` هر عملیات نشان‌دار را زیر
    <code dir="ltr">/api/store/v1/{store}/admin/…</code> گسترش می‌دهد (کلید فروشگاه به‌جای پنل، طرح احراز هویت Bearer
    کاربر، و 401 و 403 آن). [مدیران سایت](Store-API-Admins.md) را ببینید.
  - نشانگر `x-captcha` روی بدنه‌ای با فیلد `captcha`: actionی که توکن باید برای آن حل شده باشد.
- **قول Store API**: نسخه v1 فقط فیلد اضافه می‌کند — هیچ فیلدی حذف، تغییر نام یا تغییر نوع داده نمی‌شود، و درخواست همان
  چیزی را می‌پذیرد که می‌پذیرفت. تغییری که سازگاری را بشکند به‌صورت v2، کنار v1، می‌آید.

## چطور طرف PHP به آن پایبند می‌ماند

- **هر تست HTTP** (<code dir="ltr">Tests\HttpTestCase::handle()</code>، با `league/openapi-psr7-validator`) درخواست
  را پیش از ورود اعتبارسنجی می‌کند — مسیر، query، هدرها، بدنه، و نبودن بدنه جایی که عملیات بدنه‌ای نمی‌گیرد — و پاسخ را
  وقتی برمی‌گردد: وضعیت، نوع محتوا، هر فیلد. آدرسی که به هیچ مسیری نمی‌خورد فقط می‌تواند 404 یا 405 پاسخ دهد. تستی که
  هدفش درخواستی است که هیچ کلاینتی نمی‌فرستد (نوع اشتباه، فیلد جاافتاده) آن را از راه
  <code dir="ltr">unchecked()</code> می‌فرستد؛ پاسخش باز هم اعتبارسنجی می‌شود، و درخواست unchecked که معلوم شود با
  توصیف جور است تست را شکست می‌دهد.
- **تست `tests/Unit/Http/ApiDescriptionTest`** این‌ها را بررسی می‌کند:
  - فایل OpenAPI معتبر است، و ابزارهای خود یک وب‌سایت آن را همان‌طور که هست می‌خوانند
    (`league/openapi-psr7-validator` مستقیم از YAML، با محدودیت‌های پیش‌فرض parser YAML — دام‌های پایین را ببینید)؛
  - دقیقا مسیرهای برنامه را نام می‌برد (یک مسیر `{panel}` یک بار برای هر پنل، و هر مسیر مشترک پنل‌هایش را اعلام
    می‌کند)؛
  - هر عملیات تغییر، بدنه‌اش را توصیف می‌کند یا می‌گوید هیچ بدنه‌ای نمی‌گیرد؛
  - هر شیء بسته است، یا یک نگاشت (`testEveryObjectIsClosed`)؛
  - هر مسیر پنل مدیریت `X-Shop` را می‌گیرد، و مسیرهای Store API کلید و توکنشان را اعلام می‌کنند؛
  - بدنه‌ای که `captcha` دارد action خود را می‌گوید؛
  - فایل `routes/api.php` برای مدیران سایت‌ها دقیقا عملیات‌های نشان‌دار را، با مجوزهایشان، سوار (mount) می‌کند.
- **تست `tests/Feature/RouteGuardsTest`** همه مسیرها را با فیلدی که هیچ عملیاتی نمی‌گیرد، با همه بررسی‌های امنیتی به
  ترتیب، و با ردیف فروشگاه دیگر (یک 404) امتحان می‌کند.
- **تست `tests/Unit/Drivers/DriverFormsTest`** شکل‌های درخواست هر خانواده درایور را با فرم‌های درایورهای ثبت‌شده
  تطبیق می‌دهد، در هر دو جهت.

## نوع‌های تولیدشده

اسکریپت `scripts/api-types.mjs` (`pnpm api:types`) فایل `resources/panel/src/lib/api-types.ts` را می‌نویسد: برای هر
اسکیما یک نوع export‌شده، و نوشتن‌های هر API به‌صورت یک union (`PanelWrite`، `InstallWrite`، `StoreWrite`) — یک عضو
برای هر عملیات، با متدش، مسیرش (هر پارامتر به‌صورت نوع مقدارش)، بدنه‌اش و پاسخش. هرگز این فایل را دستی ویرایش نکنید؛
تا وقتی کهنه باشد `pnpm check` شکست می‌خورد. این تولیدکننده مال خود پروژه است، چون تولیدکننده معمول به API کامپایلر
TypeScript 5 نیاز دارد.

تابع <code dir="ltr">apiClient&lt;W&gt;</code> در `lib/api` هر `post`/`put`/`patch`/`delete` را بر اساس مسیرش
نوع‌دهی می‌کند: بدنه‌ای با فیلدی که عملیات نمی‌خواند، بدنه‌ای که یک فیلد الزامی را ندارد، بدنه برای نوشتنی که بدنه
نمی‌گیرد، یا آدرسی که هیچ نوشتنی ندارد، خطای کامپایل است — و پاسخ، نوع خود عملیات است. یک خواندن پاسخش را نام می‌برد
(<code dir="ltr">api.get&lt;PlansResponse&gt;('/plans')</code>).

## چطور تست‌های پنل‌ها به آن پایبند می‌مانند

هر تست پنل به‌جای `fetch` روی یک سرور فیک (`resources/panel/src/test/server`) اجرا می‌شود، و `src/test/contract` هر
درخواستی را که آن سرور دریافت می‌کند با توصیف می‌سنجد: عملیاتی که متد و مسیرش به آن می‌خورد، پارامترهای path، query و header آن، و
بدنه‌اش را با اسکیما، و هیچ چیز جایی که بدنه‌ای نمی‌گیرد. درخواستی که هیچ مسیری از تست به آن پاسخ ندهد شکست می‌خورد، و
همین‌طور درخواستی که توصیف آن را نپذیرد؛ <code dir="ltr">server().unchecked(method, path)</code> اجازه می‌دهد یک
درخواست بدشکل عبور کند، و اگر معلوم شود توصیف آن را می‌پذیرد شکست می‌خورد. این بررسی‌کننده زیرمجموعه‌ای از OpenAPI را
پیاده‌سازی می‌کند که فایل استفاده می‌کند، و روی کلیدواژه‌ای که نمی‌شناسد آشکارا شکست می‌خورد.

## تغییر API

- **اندپوینت تازه**: مسیر در `routes/api.php`، عملیات در توصیف (بدنه‌اش یا `x-no-body`، پاسخش، و `x-staff` اگر
  مدیران سایت باید آن را داشته باشند)، بعد `pnpm api:types`، بعد کد پنلی که TypeScript به آن اشاره می‌کند.
- **پاسخ تغییرکرده**: presenter، اسکیما، `pnpm api:types`.
- **درخواست تغییرکرده**: سرویسی که آن را می‌خواند، اسکیمای درخواستش، `pnpm api:types`، صفحه‌ای که آن را می‌فرستد.
- پس از هر ویرایش توصیف، `php scripts/docs.php` صفحه‌های مرجع و `docs/openapi.json` را دوباره می‌سازد.

دام‌های YAML:

- در یک نگاشت یک‌خطی `{ … }`، توضیحی (description) که کاما دارد باید داخل نقل‌قول باشد.
- یک <code dir="ltr">$ref</code> هیچ کلید هم‌سطحی نمی‌پذیرد: آن را بپیچید (<code dir="ltr">{ allOf: [{ $ref: … }], description: … }</code>).
- مجموعه‌های مشترک property از anchorها با merge keyهای <code dir="ltr">&lt;&lt;:</code> استفاده می‌کنند، و anchor
  بالای aliasهایش می‌آید.
- فیلدی تکی که جای دیگری تکرار شده **متنش** را با یک anchor روی متن description خودش به اشتراک می‌گذارد
  (<code dir="ltr">description: &amp;paymentGateway '…'</code>، بعد `description: *paymentGateway`)، هرگز با anchor روی
  کل فیلد. محافظ parser YAML در برابر alias bomb حداکثر ۱۲۸ alias از یک نگاشت یا لیست مشترک را اجازه می‌دهد، و
  ابزارهای خود یک وب‌سایت فایل را با همان محافظ، همان‌طور که می‌آید، می‌خوانند: بیشتر از آن، فایل را رد می‌کنند. aliasی
  که به یک متن ساده اشاره کند شمرده نمی‌شود. <code dir="ltr">tests/Support/ApiDescription::read()</code> فایل را به
  همان روش می‌خواند، تا تست‌ها زودتر شکست بخورند.
