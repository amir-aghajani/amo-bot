# رابط Store API: فروشگاه

آنچه هر کسی فقط با کلید فروشگاه می‌تواند بخواند: خود فروشگاه، آنچه الان می‌فروشد، و وضعیت سرورهایش. مسیرها زیر
[آدرس پایه](Store-API.md#آدرس-پایه) هستند. این‌ها را روی سرور خودتان رندر و مدت کوتاهی کش کنید
([فراخوانی از سرور شما](Store-API.md#فراخوانی-از-سرور-شما)) — به جز کاتالوگی که با توکن یک کاربر خوانده شود، که فقط مال
خود اوست ([خواندن با توکن کاربر](#خواندن-با-توکن-کاربر)).

## آنچه سایت اول می‌پرسد

درخواست <code dir="ltr">GET /</code> — نام و ربات فروشگاه، اینکه سفارش و افزودن سرویس با لینک را می‌پذیرد یا نه، اینکه
کاربران می‌توانند سرویس را به کس دیگری منتقل کنند یا سرویس دلخواه بسازند، سرویس تازه را چطور می‌توانند نام‌گذاری کنند،
راه تماس با پشتیبانی، روش‌های ورود، کپچا و شرایط برنامه زیرمجموعه‌گیری.

پاسخ `200` به <code dir="ltr">GET /</code>:
```json
{
  "shop": {
    "name": "Amo Shop",
    "bot": { "username": "amo_shop_bot", "url": "https://t.me/amo_shop_bot" },
    "taking_orders": true,
    "service_claims": false,
    "service_transfers": false,
    "custom_services": true,
    "name_modes": ["sequential", "random", "custom"]
  },
  "support": { "url": "https://t.me/amo_support" },
  "sign_in": {
    "telegram": { "client_id": "7012345678", "redirect": true },
    "google": { "client_id": "1234567890-abc123def456.apps.googleusercontent.com" },
    "email": true
  },
  "captcha": { "driver": "turnstile", "site_key": "0x4AAAAAAAAbcdEfGhIjKlMn", "challenge_url": null },
  "referral": { "enabled": true, "rate": 10, "first_only": false }
}
```

- فیلد `shop.name` — نام فروشگاه اصلی، یا عنوان ربات یک نماینده (وگرنه @username آن، وگرنه نام فروشگاه اصلی).
  `shop.bot` تا وقتی @username ربات معلوم نیست `null` است.
- فیلد `shop.taking_orders` — اینکه فروشگاه الان سفارش می‌گیرد یا نه: رباتش روشن است و — در فروشگاه یک نماینده —
  فروشگاه اصلی فروشش را متوقف نکرده. تا وقتی `false` است، هر درخواست سفارش با `503` رد می‌شود
  ([روند خرید](Store-API-Buying.md#روند-خرید) پیامش را می‌گوید و اینکه چه چیزی هنوز پذیرفته می‌شود). آنچه می‌فروشد هنوز
  خوانده می‌شود (فروشگاه نماینده‌ای که فروشش متوقف شده هیچ پلنی ندارد) و کاربران هنوز می‌توانند وارد شوند. جایی که سایت
  می‌فروشد این را به کاربر بگویید.
- فیلد `shop.service_claims` — اینکه کاربر الان می‌تواند سرویسی را با لینکش به حسابش اضافه کند یا نه (وقتی
  `taking_orders` برابر false است هم همین‌طور می‌ماند: افزودن سرویس سفارش نیست)
  ([افزودن سرویس با لینک](Store-API-After-Buying.md#افزودن-سرویس-با-لینک)): فقط در فروشگاه اصلی، و وقتی مدیر آن روشنش کرده
  باشد. تا وقتی `true` است، «افزودن سرویس» را کنار سرویس‌های کاربر نشان دهید.
- فیلد `shop.service_transfers` — اینکه کاربر الان می‌تواند یکی از سرویس‌هایش را به کاربر دیگری از فروشگاه منتقل کند یا نه
  ([انتقال سرویس به کاربر دیگر](Store-API-After-Buying.md#انتقال-سرویس-به-کاربر-دیگر)): در هر فروشگاهی، وقتی مدیرش آن را
  روشن کرده باشد. تا وقتی `true` است، «انتقال سرویس» را روی سرویس نشان دهید.
- فیلد `shop.custom_services` — اینکه کاربر الان می‌تواند سرویسی با حجم و روزهای دلخواهش بسازد یا نه
  ([سرویسی که کاربر می‌سازد](Store-API-Buying.md#سرویسی-که-کاربر-می‌سازد)): فقط در فروشگاه اصلی، وقتی مدیرش آن را روشن
  کرده باشد، هر دو لیست قیمت فروش داشته باشند و یکی از سرورهایش بتواند کلاینت تازه بگیرد؛ در فروشگاه نماینده همیشه
  `false`. تا وقتی `true` است، «ساخت سرویس دلخواه» را کنار پلن‌ها نشان دهید.
- فیلد `shop.name_modes` — روش‌هایی که خریدار می‌تواند با آن‌ها نام سرویس تازه‌اش روی پنل سرور را انتخاب کند: `sequential`
  (الگوی فروشگاه) همیشه اول، بعد `random` و `custom` اگر مدیر فروشگاه آن‌ها را گذاشته باشد. اگر فقط `sequential` باشد،
  چیزی نپرسید؛ وگرنه بگذارید کاربر در پیش‌فاکتور انتخاب کند ([خرید](Store-API-Buying.md#خرید)).
- فیلد `support.url` — راه تماس «پشتیبانی» ربات به شکل لینک: یک آدرس <code dir="ltr">https://t.me/…</code>، یک آدرس
  وب یا یک شماره <code dir="ltr">tel:</code>؛ اگر چیزی تنظیم نشده یا فقط متن ساده است `null`.
- فیلد `sign_in` — [روش‌های ورود](Store-API-Sign-In.md#روش‌های-ورود). `captcha` — `null`، یا کپچایی که فرم‌های وب‌سایت
  می‌خواهند و طرز نمایش آن ([کپچا](Store-API-Sign-In.md#کپچا)).
- فیلد `referral` — `rate` درصد از آنچه کاربر معرفی‌شده می‌پردازد، یا با `first_only` فقط از اولین پرداختش
  ([برنامه زیرمجموعه‌گیری](Store-API-After-Buying.md#برنامه-زیرمجموعه‌گیری)).

## آنچه می‌فروشد

پاسخ `GET /plans` دقیقا همان چیزی است که «خرید اشتراک» ربات الان نشان می‌دهد: هر دسته‌بندی فعال به ترتیب ربات —
دسته‌بندی خالی هم — و بعد پلن‌هایی که دسته‌بندی ندارند (یا دسته‌بندی‌شان خاموش است) در یک گروه آخر با <code dir="ltr">"category": null</code>.
پلن فقط تا وقتی می‌آید که بشود تحویلش داد: روشن باشد، روی سروری باشد که بتواند آن را بفروشد، و — در فروشگاه یک
نماینده — حجم نماینده برایش کافی باشد و فروشگاه اصلی فروشش را نبسته باشد (سرورهایی که
فروشگاه اصلی از نماینده پنهان می‌کند هم چیز تازه‌ای نمی‌فروشند). فروشگاه بدون دسته‌بندی همین یک گروه را دارد، یا اگر
الان چیزی نمی‌فروشد هیچ گروهی. اگر با توکن یک کاربر خوانده شود، همان چیزی است که ربات به آن کاربر نشان می‌دهد
([خواندن با توکن کاربر](#خواندن-با-توکن-کاربر)).

پاسخ `200` به `GET /plans`:
```json
{
  "groups": [
    {
      "category": { "id": 1, "name": "یک ماهه" },
      "plans": [
        {
          "id": 3,
          "name": "یک ماهه ۵۰ گیگ",
          "description": "مناسب استفاده روزانه",
          "checkout_note": "روی Happ و v2rayNG تست شده است.",
          "price": "120000.00",
          "first_purchase_price": "90000.00",
          "agent_price": null,
          "offer_price": "72000.00",
          "discount": { "source": "sale", "label": "فروش ویژه نوروز ۲۰٪", "percent": 20, "ends_at": "2026-03-21T20:30:00+00:00" },
          "traffic_gb": 50,
          "duration_days": 30,
          "duration_hours": 720,
          "devices": 2,
          "category_id": 1,
          "locations": [{ "id": 1, "name": "آلمان" }, { "id": 2, "name": "هلند" }]
        }
      ]
    },
    {
      "category": null,
      "plans": [
        {
          "id": 7,
          "name": "نامحدود سه ماهه",
          "description": null,
          "checkout_note": null,
          "price": "450000.00",
          "first_purchase_price": null,
          "agent_price": null,
          "offer_price": "450000.00",
          "discount": null,
          "traffic_gb": 0,
          "duration_days": 90,
          "duration_hours": 2160,
          "devices": 0,
          "category_id": null,
          "locations": [{ "id": 2, "name": "هلند" }]
        },
        {
          "id": 9,
          "name": "تست یک ساعته",
          "description": "برای اولین آشنایی",
          "checkout_note": null,
          "price": "5000.00",
          "first_purchase_price": "0.00",
          "agent_price": null,
          "offer_price": "0.00",
          "discount": null,
          "traffic_gb": 1,
          "duration_days": 1,
          "duration_hours": 1,
          "devices": 1,
          "category_id": null,
          "locations": [{ "id": 1, "name": "آلمان" }]
        }
      ]

```

| فیلد | معنا |
|---|---|
| `checkout_note` | یادداشتی که در پیش‌فاکتور همراه پلن نشان داده می‌شود («یادداشت پیش‌فاکتور» — برنامه‌هایی که پلن روی آن‌ها تست شده، یک هشدار)، متن ساده: escape کنید و شکستگی خط‌هایش را نگه دارید؛ اگر نباشد `null` |
| `price` | تومان |
| `first_purchase_price` | آنچه کاربر برای آن به‌عنوان اولین خریدش در فروشگاه می‌پردازد («قیمت خرید اول»)، به تومان — کمتر از `price`، و `"0.00"` یعنی اولین خرید رایگان؛ اگر نباشد `null`، یا — با توکن یک کاربر — وقتی او سرویسی خریده باشد ([قیمت خرید اول](#قیمت-خرید-اول)) |
| `agent_price` | آنچه نماینده‌ها و همکاران فروشگاه برای آن می‌پردازند («قیمت نماینده»)، به تومان — کمتر از `price`؛ اگر نباشد `null`، و همین‌طور برای هر کس دیگر: یک مهمان، کاربری که هیچ‌کدام از این دو نیست ([قیمت نماینده](#قیمت-نماینده)) |
| `offer_price` | آنچه خواننده امروز برای آن می‌پردازد، به تومان: کمترین قیمتش که مال اوست، منهای بزرگ‌ترین تخفیف خودکارش؛ تا وقتی تخفیفی نیست همان `price`. همین را به‌عنوان قیمت نشان دهید ([تخفیف‌ها](#تخفیف‌ها)) |
| `discount` | تخفیف خودکاری که `offer_price` کم کرده — `source` (`sale`، `personal` یا `tier`)، `label` (به زبان کاربر: «فروش ویژه نوروز ۲۰٪»، «تخفیف اختصاصی شما ۱۰٪»، «سطح طلایی ۵٪»)، `percent`، و `ends_at` یک فروش ویژه (وگرنه `null`) —؛ اگر نباشد `null` |
| `traffic_gb` | گیگابایت، با اعشار مجاز؛ `0` نامحدود |
| `duration_hours` | مدت، دقیقا، به ساعت — که از **اولین اتصال** کاربر شمرده می‌شود؛ `0` هرگز تمام نمی‌شود. پلنی ممکن است ساعتی فروخته شود (یک تست یک‌ساعته)؛ پلنی با روزهای کامل، روزهایش × ۲۴ را می‌گوید |
| `duration_days` | همان مدت به روز کامل، رو به بالا گرد شده — پلن یک‌ساعته `1` می‌گوید؛ `0` هرگز تمام نمی‌شود. برای سایت‌هایی نگه داشته شده که پیش از `duration_hours` ساخته شده‌اند: مدت را از روی `duration_hours` نشان دهید |
| `devices` | تعداد دستگاه هم‌زمان؛ `0` بدون محدودیت |
| `category_id` | دسته‌بندی‌ای که زیر آن فهرست شده؛ برای گروه آخر `null` |
| `locations` | سرورهایی که امروز می‌شود آن را رویشان خرید («لوکیشن» در ربات)، به ترتیب پلن — دست‌کم یکی؛ کاربر یکی را انتخاب می‌کند، که در پیش‌فاکتور همان `server_id` می‌شود |

پاسخ <code dir="ltr">GET /plans/{id}</code> یک پلن با همین شکل است، <code dir="ltr">{ "plan": … }</code>، یا `404` برای
پلنی که فروشگاه الان نمی‌فروشد (خاموش است، روی هیچ سروری نیست که بتواند تحویلش دهد، یا — در فروشگاه یک نماینده — حجم
نماینده برایش کافی نیست یا فروشگاه اصلی فروشش را بسته). قیمت‌ها و لوکیشن‌ها با تغییرات فروشگاه عوض می‌شوند: مدت کوتاهی
کش کنید (یک دقیقه) و پیش از پیش‌فاکتور دوباره بخوانید.

### خواندن با توکن کاربر

درخواست‌های `GET /plans` و <code dir="ltr">GET /plans/{id}</code> برای همه باز است، با توکن یا بدون آن. اگر با توکن
Bearer یک کاربر فرستاده شوند، کاتالوگ را همان‌طور برمی‌گردانند که ربات به همان کاربر نشان می‌دهد: قیمت‌های خرید اول،
که وقتی خرید کرده باشد `null` می‌شوند، و قیمت‌های نماینده، که جز برای نماینده یا همکار `null` هستند. توکنی که هیچ
Sessionی را باز نمی‌کند — منقضی‌شده، خارج‌شده، مال فروشگاه دیگر — همان `401` همه اندپوینت‌های کاربر را می‌گیرد
(`WWW-Authenticate: Bearer`)، و هرگز کاتالوگ مهمان به جایش برنمی‌گردد: مثل هر جای دیگر توکن را کنار بگذارید
([توکن‌ها و Sessionها](Store-API-Sign-In.md#توکن‌ها-و-sessionها)) و کاتالوگ را بدون آن دوباره بخوانید. کاربر مسدود
`403` می‌گیرد. فقط آنچه را بدون توکن خوانده‌اید کش کنید؛ آنچه یک کاربر برای خودش می‌خواند فقط مال خود اوست.

### قیمت خرید اول

یک پلن ممکن است برای اولین خرید کاربر قیمت جداگانه‌ای داشته باشد، `first_purchase_price` («قیمت خرید اول»): مبلغی که
کاربری که هیچ‌وقت در فروشگاه سرویسی نخریده برای آن می‌پردازد — خریدی که پرداخت شده و پس داده نشده (تحویل‌شده، در حال
تحویل، یا ناموفق و منتظر پشتیبانی) خرید حساب می‌شود؛ خریدی که بعدا بازپرداخت شده خرید حساب نمی‌شود، و همین‌طور سفارشی
که هیچ‌وقت پرداخت نشده، سفارشی که پرداخت‌نشده لغو شده، سرویسی که رایگان داده شده و شارژ کیف پول. هر پلن به همه فروخته
می‌شود: فقط قیمتش فرق می‌کند. هر فروشگاه خریدهای کاربران خودش را می‌شمارد.

- **مهمان** آن را روی هر پلنی که چنین قیمتی دارد می‌بیند: آن را به‌عنوان قیمت اولین خرید نشان دهید، با `price` کنارش
  — `"0.00"` یعنی اولین خرید رایگان است.
- **کاربری که خرید نکرده** با توکنش هم آن را مثل مهمان می‌بیند، و `POST /orders` همین مبلغ را از او می‌گیرد
  ([خرید](Store-API-Buying.md#خرید))؛ `amount` سفارش مبلغی است که سفارش با آن ثبت شده.
- **کاربری که خرید کرده** روی همه پلن‌ها `null` می‌بیند: او `price` را می‌پردازد. درخواستی که با همان `Idempotency-Key`
  دوباره فرستاده شود هنوز همان سفارش قبلی را با مبلغ خودش برمی‌گرداند.
- **دو خرید هم‌زمان** — هر دو با قیمت خرید اول، یا با کدی که فقط برای اولین خرید است، پیش از پرداخت هیچ‌کدام ثبت
  شده‌اند —: آنکه اول پرداخت شود اولین خرید اوست و دیگری هیچ‌وقت تحویل نمی‌شود. آن سفارش `failed` است، با `failure`
  برابر `first_purchase_used` ([چرا سفارش ناموفق شد](Store-API-Buying.md#چرا-سفارش-ناموفق-شد))، و پشتیبانی پرداخت را
  با کاربر تسویه می‌کند؛ اعلان `payment_settled` آن دلیلش را به او می‌گوید.
- **سرویس آن با `price` تمدید می‌شود**، چه کاربر تمدیدش کند و چه خودکار تمدید شود
  ([تمدید سرویس](Store-API-Buying.md#تمدید-سرویس)) — برای نماینده یا همکار با `agent_price`.

### قیمت نماینده

یک پلن ممکن است قیمتی برای فروشنده‌های فروشگاه داشته باشد، `agent_price` («قیمت نماینده»): مبلغی که نماینده فروشگاه
برای آن می‌پردازد، و همین‌طور کاربری از گروهی که فروشگاه آن را «همکار» کرده — یک همکار. برای بقیه `null` است: مهمان
هیچ‌وقت آن را نمی‌بیند، و کاربری که نه نماینده است و نه همکار هم نمی‌بیند.

- **با توکن**، `agent_price` نماینده یا همکار همان مبلغی است که می‌پردازد: آن را به‌عنوان قیمت پلن برای او نشان دهید،
  با `price` کنارش. `POST /orders` همین مبلغ را می‌گیرد، و تمدیدهایش هم، چه خودش تمدید کند و چه خودکار، با همین قیمت
  است.
- **همراه قیمت خرید اول** — همکاری که هنوز چیزی نخریده هر دو را می‌بیند و کمترینشان از او گرفته می‌شود.
- **سفارش می‌گوید** با کدام قیمت ثبت شده: `pricing` — `regular`، `first_purchase` یا `agent`
  ([پاسخ درخواست سفارش](Store-API-Buying.md#پاسخ-درخواست-سفارش)).

### تخفیف‌ها

مبلغی که کاربر می‌پردازد در سه قدم حساب می‌شود، با همان یک قاعده فروشگاه (که ربات هم از آن پیروی می‌کند):

1. **پایه** — کمترین قیمتی از پلن که شامل او می‌شود (`price`، `first_purchase_price`، `agent_price`).
2. **بزرگ‌ترین تخفیف خودکار** روی آن — فروش ویژه زمان‌دار روی پلن («فروش ویژه»)، درصد اختصاصی خود کاربر («تخفیف
   اختصاصی»، که پشتیبانی تعیین می‌کند) یا تخفیف سطح وفاداری‌اش — و هیچ‌وقت دو تخفیف با هم جمع نمی‌شوند. `offer_price`
   پایه منهای آن است و `discount` می‌گوید کدام تخفیف بوده. مهمان فقط فروش‌های ویژه را می‌بیند؛ با توکن، تخفیف اختصاصی
   کاربر و تخفیف سطحش هم حساب می‌شوند. فروش ویژه در `discount.ends_at` تمام می‌شود: بعد از آن کاتالوگ را دوباره بخوانید.
3. **کد تخفیفی** که کاربر وارد می‌کند، روی مبلغی که از قدم ۲ مانده — در پیش‌فاکتور، با `discount_code`
   ([کدهای تخفیف](Store-API-Buying.md#کدهای-تخفیف))؛ `POST /discount-codes/check` قیمت با کد را پیش از پرداخت نشان
   می‌دهد.

شارژ کیف پول هیچ‌وقت تخفیف نمی‌گیرد. تمدید و حجم، زمان یا کاربر اضافه همان تخفیف خودکار را می‌گیرند (فروش ویژه بر اساس
پلن سرویس) و کد تخفیف هم می‌پذیرند.

## وضعیت سرورها

پاسخ `GET /status` — سرورهای پلن‌های روشن فروشگاه، به ترتیب سرورها (در فروشگاه یک نماینده، بدون آن‌هایی که فروشگاه
اصلی از او پنهان می‌کند) — و هیچ‌وقت آدرس‌ها، کانکتورها یا پاسخ پنل‌هایشان. پلن روشنی که `GET /plans` نمی‌آوردش (هیچ
جا نمی‌شود تحویلش داد، یا حجم نماینده برایش کافی نیست) باز هم سرورهایش را اینجا می‌آورد.

پاسخ `200` به `GET /status`:
```json
{
  "servers": [
    { "id": 1, "name": "آلمان", "available": true, "checked_at": "2026-10-08T09:30:12+00:00" },
    { "id": 2, "name": "هلند", "available": true, "checked_at": "2026-10-08T09:30:09+00:00" },
    { "id": 3, "name": "فرانسه", "available": false, "checked_at": "2026-10-08T09:29:58+00:00" }
  ]
}
```

فیلد `available` — اینکه خود سرور الان کاربر تازه می‌پذیرد یا نه (روشن است، بررسی شده، لینک اشتراک می‌دهد و جا دارد)؛
سروری که آخرین تماس با آن ناموفق بوده هنوز در دسترس حساب می‌شود، چون ربات هنوز رویش می‌فروشد. چیزی درباره پلن‌ها
نمی‌گوید: اینکه پلنی روی یک سرور خریدنی است یا نه را فقط `locations` آن در `GET /plans` می‌گوید. `checked_at` — آخرین
باری که فروشگاه با آن تماس گرفته، و اگر هیچ‌وقت نگرفته `null`.
