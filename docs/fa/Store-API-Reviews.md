# رابط Store API: نظرات

نظرهای کاربران فروشگاه: نظرهایی را که پشتیبانی تایید کرده هر کسی می‌تواند بخواند، و نظر را یا کاربری که وارد شده
می‌نویسد — که در این صورت به حسابش وصل می‌شود — یا، با گذشتن از کپچای وب‌سایت، یک مهمان. پشتیبانی درباره هر نظر در
«نظرات» پنل‌ها یا بخش مدیریت وب‌سایت ([مدیران سایت](Store-API-Admins.md)) تصمیم می‌گیرد؛ تا آن موقع وب‌سایت چیزی از آن
نشان نمی‌دهد. مسیرها زیر [آدرس پایه](Store-API.md#آدرس-پایه) هستند.

**وب‌سایت فقط وقتی نظرات را نشان می‌دهد که فروشگاه بخواهد**: با کلید «تنظیمات وب‌سایت › نظرات» در پنل
([وب‌سایت](Website.md#نظرات))، که برای وب‌سایت تازه خاموش است. وقتی خاموش است، `GET` و `POST /reviews` هر دو `404`
برمی‌گردانند (`این وب‌سایت نظرات مشتریان را نشان نمی‌دهد و نظری نمی‌گیرد.`): نظرات و فرم آن را پنهان کنید.

## نظرهایی که فروشگاه نشان می‌دهد

پاسخ `200` به <code dir="ltr">GET /reviews?page=</code>:
```json
{
  "reviews": [
    {
      "id": 31,
      "name": "مریم",
      "rating": 5,
      "body": "از اول ماه وصلم و مشکلی نداشتم.\nپشتیبانی هم سریع جواب داد.",
      "context": "ایرانسل · اندروید · Happ",
      "avatar": "fox",
      "created_at": "2026-10-06T19:22:41+00:00"
    }
  ],
  "meta": { "page": 1, "per_page": 25, "total": 18, "last_page": 1, "summary": { "count": 18, "average": 4.61 } }
}
```

- فقط نظرهای تاییدشده، جدیدترین اول، ۲۵ نظر در هر صفحه — بدون توکن و برای همه.
- فیلد `body` شکستگی خط‌هایش را نگه می‌دارد (آن را با `white-space: pre-line` نشان دهید)؛ `name`، `body` و `context`
  متن ساده‌ای هستند که نویسنده تایپ کرده: آن‌ها را escape کنید و هرگز به شکل HTML نشان ندهید. `context` — اینکه از کجا
  از سرویس استفاده می‌کند — و `avatar` — کلید یکی از آواتارهای خود سایت شما، همان که نویسنده انتخاب کرده — ممکن است
  `null` باشند: پیش‌فرض خودتان را نشان دهید.
- فیلد `meta.summary` درباره همه نظرهای تاییدشده است، در هر صفحه‌ای که باشید: تعدادشان و میانگین امتیازشان با دو رقم
  اعشار — تا وقتی نظری نیست `null`؛ میانگین بدون اعشار به شکل عدد صحیح می‌آید (`5`)، پس آن را عدد بخوانید.
- چیزی از نویسنده نظر یا از کار پشتیبانی روی آن در پاسخ نیست: نه حسابی، نه وضعیتی، نه تصمیمی.

لیست را روی سرور خودتان بسازید و مدت کوتاهی نگه دارید، مثل کاتالوگ
([فراخوانی از سرور شما](Store-API.md#فراخوانی-از-سرور-شما)).

## ثبت نظر

درخواست `POST /reviews`:
```json
{ "name": "مریم", "rating": 5, "body": "از اول ماه وصلم و مشکلی نداشتم.", "context": "ایرانسل · اندروید · Happ", "avatar": "fox", "captcha": "…" }
```

پاسخ `201` به `POST /reviews`:
```json
{ "review": { "id": 32, "status": "pending" } }
```

| فیلد | قاعده |
|---|---|
| `name` | ۲ تا ۶۴ کاراکتر، در یک خط (فاصله‌ها و شکستگی خط‌ها یک فاصله می‌شوند): نامی که نظر با آن امضا می‌شود |
| `rating` | ۱ تا ۵ — یک عدد JSON یا متن آن، با رقم فارسی هم |
| `body` | ۱۰ تا ۶۰۰ کاراکتر، با همان شکستگی خط‌ها |
| `context` | اختیاری، حداکثر ۱۰۰ کاراکتر، در یک خط: اینکه از کجا از سرویس استفاده می‌کند — «ایرانسل · اندروید · Happ» |
| `avatar` | اختیاری: کلید یکی از آواتارهای خود سایت شما — ۱ تا ۳۲ کاراکتر از <code dir="ltr">a-z 0-9 - \_</code>، هرگز یک آدرس |
| `captcha` | تا وقتی `captcha` در <code dir="ltr">GET /</code> برابر `null` نیست: توکن ویجت، حل‌شده برای action `review` ([کپچا](Store-API-Sign-In.md#کپچا)) |

**چه کسی آن را می‌نویسد**: با توکن Bearer کاربری که وارد شده، نظر مال اوست — پشتیبانی حسابش را کنار نظر می‌بیند —؛
توکنی که هیچ Sessionی را باز نمی‌کند `401` می‌گیرد (و هرگز به جای آن نظر مهمان ثبت نمی‌شود)، و کاربر مسدود `403`. بدون
توکن، نظر مال یک مهمان است و **فقط تا وقتی وب‌سایت کپچا می‌خواهد پذیرفته می‌شود**: بدون کپچا چیزی جلوی ربات‌ها را
نمی‌گیرد، پس نظر مهمان `403` می‌گیرد (`برای نوشتن نظر، اول وارد حساب خود شوید.`) — ورود را پیشنهاد کنید، یا از مالک
فروشگاه بخواهید کپچا را روشن کند. فیلد `captcha` در <code dir="ltr">GET /</code> وضعیت را می‌گوید: اگر `null` است، فرم را
فقط به کاربرانی که وارد شده‌اند نشان دهید.

**پاسخ `201` و `pending` است**: به نویسنده بگویید نظرش بعد از تایید پشتیبانی نشان داده می‌شود. به کسی از تصمیم خبر
داده نمی‌شود — برای دیدنش `GET /reviews` را دوباره بخوانید.

**به این ترتیب** بررسی می‌شود، و هر جا بشود همه خطاها با هم گفته می‌شوند:

1. درخواست‌کننده — `401` برای توکن یا `403` برای کاربر مسدود؛ بعد `404` تا وقتی نظرات وب‌سایت خاموش است؛ بعد `403`
   برای نظر مهمان بدون کپچا.
2. فیلدها — `422` زیر هر فیلد ردشده، همه با هم: `نام خود را بنویسید.`، `نام حداقل 2 کاراکتر است.`،
   `نام حداکثر 64 کاراکتر است.`، `امتیاز باید عددی بین 1 تا 5 باشد.`، `متن نظر را بنویسید.`،
   `متن نظر حداقل 10 کاراکتر است.`، `متن نظر حداکثر 600 کاراکتر است.`، `مشخصات حداکثر 100 کاراکتر است.`، و برای
   آواتاری که کلید نیست `آواتار باید کلید یکی از آواتارهای خود وب‌سایت باشد: …`.
3. ظرفیت فروشگاه — `503` (`این فروشگاه الان نظر تازه‌ای نمی‌گیرد؛ کمی بعد دوباره امتحان کنید.`) تا وقتی ۲۰۰ نظر منتظر
   پشتیبانی‌اند: بعدا دوباره امتحان کنید.
4. سرعت نویسنده — `429` با `Retry-After` (`نظر زیادی ثبت شده است؛ …`): ۲۰ نظر در ساعت از یک شبکه (آدرس IPv6 با
   <code dir="ltr">/48</code> آن شمرده می‌شود)، ۳ نظر در روز از هر کاربر واردشده، و ۲۰ نظر در ساعت از همه مهمان‌ها با هم
   — کل دفتر مهمان فروشگاه.
5. کپچا — `422` روی `captcha` (`تایید امنیتی انجام نشد؛ دوباره تلاش کنید.`): توکن ردشده باز هم در سهمیه شبکه و سهمیه خود
   کاربر واردشده شمرده می‌شود، ولی هرگز در سهمیه همه مهمان‌ها با هم؛ `503` وقتی الان نمی‌شود آن را سنجید
   (`تایید امنیتی در دسترس نیست؛ کمی بعد دوباره تلاش کنید.`)، که چیزی را نمی‌شمارد. بعد از هر پاسخ، ویجت را ریست کنید.

نظر را از مرورگر بازدیدکننده بفرستید: سرعت با آدرسی شمرده می‌شود که درخواست از آن می‌آید — اگر از سرور شما برود، همه
بازدیدکننده‌ها همان یک آدرس را خواهند داشت.

```ts
// A review written on the site: the visitor's token when one is kept — theirs then —, the widget's token always.
export async function writeReview(input: { name: string; rating: number; body: string; context?: string; avatar?: string }, captcha?: string) {
  const { review } = await store<S['StoreReviewWrittenResponse']>('/reviews', { method: 'POST', json: { ...input, captcha } })
  return review.status // 'pending': say it shows once approved
}
```
