# مستندات AmoBot

برنامه AmoBot یک فروشگاه متن‌باز برای فروش اشتراک VPN است. کاربران در یک ربات تلگرام سرویس‌هایشان را می‌خرند،
هزینه‌اش را می‌پردازند و مدیریتشان می‌کنند؛ مالک فروشگاه آن را از یک پنل وب (`/admin/`) اداره می‌کند، و هر نماینده، یعنی فروشنده‌ای
با ربات و فروشگاهی از آن خودش، از پنل خودش (`/agent/`)؛ وب‌سایت خود فروشگاه هم می‌تواند از راه Store API بفروشد. AmoBot
هر سرویس را روی پنل‌های VPN که به آن‌ها وصل است (3X-UI، PasarGuard) می‌سازد، و پول را با روش‌های پرداختی می‌گیرد که
مالک فروشگاه تنظیم کرده است.

این برنامه روی هاست اشتراکی، مثل cPanel و DirectAdmin، اجرا می‌شود و این تنها روش پشتیبانی‌شده است: PHP به یک API از
نوع JSON پاسخ می‌دهد، پنل‌ها فایل‌های ایستا هستند، یک نصب‌کننده وب همه چیز را از مرورگر راه‌اندازی می‌کند، Cron هاست
زمان‌بند آن را اجرا می‌کند و تلگرام از راه Webhook به ربات‌هایش می‌رسد. هر چه کاربر یا مالک فروشگاه می‌بیند فارسی و راست
به چپ است؛ کد به انگلیسی است، و این صفحه‌ها اول به انگلیسی نوشته می‌شوند.

## مالکان فروشگاه

راه‌اندازی فروشگاه، به ترتیب:

1. [نصب](Installation.md): آنچه هاست لازم دارد، فایل zip نسخه، نصب‌کننده وب.
2. [اجرا روی هاست](Running-In-Production.md): دریافت پیام‌های ربات، زمان‌بند، چک‌لیست، لاگ‌ها، و برگشتن به پنل وقتی
   رمز یا نام کاربری‌اش را گم کرده‌اید.
3. [راهنمای مالک فروشگاه](Owners-Guide.md#راه‌اندازی-فروشگاه): یک سرور، یک پلن و یک روش پرداخت، و بعد بقیه فروشگاه.

بعد، وقتی فروشگاه کار می‌کند:

| برای | بخوانید |
|---|---|
| کار با پنل‌ها، صفحه به صفحه | [راهنمای مالک فروشگاه](Owners-Guide.md#صفحه‌ها) و صفحه‌های آن |
| دیدن آنچه کاربران و مدیران ربات در ربات می‌بینند | [راهنمای ربات](Bot-Guide.md) |
| وصل کردن وب‌سایت خود فروشگاه | [وب‌سایت](Website.md) |
| تغییر تنظیمات نصب | [پیکربندی](Configuration.md) و [مرجع config.php (انگلیسی)](../Config-Reference.md) |
| نصب نسخه تازه | [به‌روزرسانی](Upgrading.md) |
| پشتیبان گرفتن از فروشگاه | [پشتیبان‌گیری](Backups.md) |

هیچ‌کدام از این‌ها به کنسول نیاز ندارد: نصب‌کننده وب، پنل‌ها و کنترل‌پنل هاست همه کارها را انجام می‌دهند.
[دستورهای کنسول](Console-Commands.md) ابزار توسعه‌دهنده‌اند، و فقط جایی به کار فروشگاه می‌آیند که هاستش ترمینال داشته
باشد.

## توسعه‌دهندگان وب‌سایت

رابط [Store API](Store-API.md) راهی است که وب‌سایت خود فروشگاه با آن کاربرانش را وارد می‌کند، به آن‌ها می‌فروشد و
کارهایشان را انجام می‌دهد. از نمای کلی آن شروع کنید (آدرس پایه، CORS، قراردادها، خطاها و یک کلاینت ساده)، و بعد هر موضوع
در یک صفحه: [ورود](Store-API-Sign-In.md)، [حساب کاربری](Store-API-Account.md)، [فروشگاه](Store-API-Shop.md)،
[خرید](Store-API-Buying.md)، [بعد از خرید](Store-API-After-Buying.md)، [اعلان‌ها](Store-API-Notifications.md)،
[تیکت‌های پشتیبانی](Store-API-Support-Tickets.md)، [نظرات](Store-API-Reviews.md) و
[مدیران سایت](Store-API-Admins.md). همه عملیات‌ها در [مرجع (انگلیسی)](../Store-API-Reference.md) آن آمده‌اند که خودکار
ساخته می‌شود، و عملیات‌های مدیران سایت در [مرجع API مدیران (انگلیسی)](../Store-Admin-API-Reference.md).

## مرجع‌ها

- [مرجع config.php (انگلیسی)](../Config-Reference.md): همه تنظیمات پیکربندی نصب، که از روی کد ساخته می‌شود.

  [API مدیران](../Store-Admin-API-Reference.md) آن برای مدیران سایت در همان وب‌سایت، [API پنل‌ها](../Panels-API-Reference.md)
  برای مشارکت‌کنندگان، و [اسکیماهایی](../API-Schemas.md) که میان آن‌ها مشترک است؛ و خود توصیف، به‌صورت یک فایل برای
  ابزارها: [`docs/openapi.json`](https://github.com/amir-aghajani/amo-bot/blob/main/docs/openapi.json).
